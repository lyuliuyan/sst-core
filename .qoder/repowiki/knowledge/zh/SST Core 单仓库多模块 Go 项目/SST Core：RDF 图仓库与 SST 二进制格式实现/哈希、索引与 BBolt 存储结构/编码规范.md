- BBolt 键采用「单字节前缀 + 数据」的组合方式（如 `dsPrefix`、`ngPrefix`、`refBranchPrefix`），并通过 `bytesToKeyInternal`/`iDToPrefixedKey` 统一构造，避免散落的字符串拼接。
- 哈希值以固定 44 字符的 Base58 字符串表示，短串用 `base58StringPrePadding` 前补零，解析时先 decode 再裁剪至 32 字节，保证双向一致性。
- 索引更新全部走 `defaultBleveIndexUpdater` 的 channel 队列，调用方只负责捕获必要上下文并提交函数，实际 I/O 在后台 goroutine 中串行执行，避免阻塞 BBolt 事务。
- 对 bleve 的操作统一经 `healthAwareIndex` 代理，每次 Index/Delete/Batch/Search 成功后调用 `recordSuccess`、失败调用 `recordError`，并在 Search 中对特定 IO 错误进行一次性重试。
- 批量索引通过 `indexBatch` 累积文档并在超过 `maxBatchDocSize` 时自动 flush，同时收集 `batchPreCondition` 查询，在批次提交后再统一校验唯一性约束。
- 分支相关索引操作仅在 `branch == DefaultBranch` 时生效，非默认分支直接 return，使默认分支成为唯一被索引的可见分支。
