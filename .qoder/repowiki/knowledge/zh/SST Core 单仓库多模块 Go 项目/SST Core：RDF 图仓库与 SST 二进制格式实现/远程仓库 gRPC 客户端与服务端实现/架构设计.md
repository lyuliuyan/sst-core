本模块由三部分组成：
- `reporemote.go`：定义 `remoteRepository`、`remoteDataset`、`remoteIndex` 等结构体，作为 `SuperRepository`/`Repository`/`Dataset`/`bleve.Index` 接口的远程代理；通过 `dialRepository` 建立 `grpc.ClientConn`，并持有 `bboltproto.DatasetServiceClient`、`CommitServiceClient`、`bleveproto.IndexServiceClient` 三个子服务客户端；所有公开方法统一通过 `stateControl.enter()/leave()` 进行生命周期守卫，使用原子状态机（Open/Closing/Closed）+ WaitGroup 保证并发安全关闭；对 Bleve 搜索采用流式 gRPC 调用并通过 `remoteRequestCache` 缓存 `grpc.PreparedMsg` 以复用请求。
- `reporemoteapp.go`：服务端侧，定义 `RepositoryServer`、`indexServiceServer`，在 `newRepositoryServer` 中注册 DatasetService、RefService、CommitService、IndexService 四个 gRPC 服务；通过 `repositoryMethodRoles` 映射每个方法到最小 `AccessMode`，配合 `sstauth.UnaryRBACInterceptor` / `StreamRBACInterceptor` 实现基于 OIDC token 的 RBAC；支持可选 TLS、恢复拦截器、日志拦截器；提交后通过 `FlushBleveIndex` 确保索引可见性。
- `reporemotecommit.go`：实现 `commitServiceServer`，将 `CreateCommit` 中的 NamedGraph 字节流反序列化为 Stage 后合并入本地仓库，再调用 `stage.Commit` 生成 commit，并返回签名信息供客户端同步 checkout 状态。
依赖方向：客户端 → bboltproto/bleveproto 定义的 gRPC 接口；服务端 → 本地仓库实现（localFullRepository），不反向依赖客户端代码。
