模块以 `main.go` 为可执行入口，加载 `.env.sst-cli` 后创建 `Session` 并通过 `RunStdio` 启动基于 `github.com/modelcontextprotocol/go-sdk/mcp` 的 MCP Server，传输层使用 `StdioTransport`。

内部按职责拆分为四个文件：
- `server.go`：`NewServer` 构造 MCP Server，用泛型辅助 `addTool[T]` 注册约 20 个工具（repository/dataset/stage/document/status），所有工具处理器统一通过 `textResult` 将返回值序列化为 JSON TextContent；`RunStdio` 是对外唯一启动入口。
- `session.go`：`Session` 结构体持有并发安全的 repo/dataset/stage 句柄表（各含 alias→handle、order 列表及反向映射），通过 `reserveXxxAlias`/`commitXxx` 模式分配 rN/dN/sN 别名并维护生命周期；实现仓库打开/关闭、数据集浏览、提交历史遍历、分支 checkout、stage 验证/TriG 导出/提交、文档上传下载删除等核心业务。
- `remote.go`：封装远程仓库连接，从 `utils.GetToken` 读取 OIDC token 构造 `staticTokenProvider`，注入 `sstauth.ContextWithAuthProvider` 并通过 gRPC TLS 打开远程仓库；`authContextFor` 复用已缓存的认证上下文。
- `document_helpers.go`：提供 MIME 类型推断、扩展名映射与文档元数据格式化等纯函数。

依赖方向单向：`main → server → session → sst/sstauth/tools/validate/cli/utils`，MCP SDK 仅用于协议适配，业务逻辑完全委托给 SST Core。
